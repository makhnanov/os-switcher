# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Проект и его документация — на русском, отвечать и комментировать тоже по-русски.

## Что это

Аппаратный выбор пункта GRUB: плата Pro Micro (ATmega32u4) прикидывается
USB-клавиатурой и жмёт стрелки с Enter, а в загруженной ОС по щелчку
выключателя на `D2` заказывает перезагрузку через демон на хосте. Разводка,
тайминги, объяснения про светодиоды и USB-триггер — в `README.md`, установка —
в `INSTALL.md`; здесь только то, что важно при правке кода.

Тестов и линтеров нет, проверка — только ручная (см. ниже). Файл `test` в корне
к проверке отношения не имеет — это случайно закоммиченный мусор.

## Команды

```bash
make                    # собрать и прошить (то же, что make flash)
make build              # только собрать
make flash PORT=/dev/ttyACM0   # прошить в конкретный порт
make ports              # список подключённых плат
make install-service    # поставить сервис на хосте (Linux, sudo)
make service-logs       # журнал сервиса
make uninstall-service  # снять
```

Windows-часть Makefile не покрывает, она ставится своим установщиком:

```powershell
powershell -ExecutionPolicy Bypass -File host\windows\install.ps1
powershell -ExecutionPolicy Bypass -File host\windows\install.ps1 -Uninstall
```

## Из чего состоит

Прошивка и два слушателя, связанные одним протоколом (таблица — в README):

- `os-switcher-sketch/os-switcher-sketch.ino` — вся логика в `loop()`, триггер
  по фронту `USBDevice.configured()`; шлёт в USB-serial `COUNTDOWN <сек>`,
  `CANCEL`, `REBOOT`;
- `host/linux/os-switcher-rebootd.py` + `.service` + `99-os-switcher.rules` —
  systemd-сервис от root, `notify-send` от владельца активной сессии;
- `host/windows/os-switcher-rebootd.ps1` + `install.ps1` — то же через toast и
  `shutdown.exe /r /t 0`. Задача планировщика «при входе в систему», файлы в
  `%LOCALAPPDATA%\os-switcher\`.

Длительность отсчёта задаёт **плата** (`REBOOT_HOLD_MS`), хост берёт её из
аргумента `COUNTDOWN`. Добавляешь команду — правь **оба** слушателя (`serve()`
в Python, разбор `$text` в PowerShell) и таблицу протокола в README.

## Инварианты, которые легко сломать

**Рядом воткнута плата `off-screen`, и `VID:PID` у неё ровно тот же
(`2341:8036`).** Различает их только `iProduct` из USB-дескриптора. Искать
плату по одному `VID:PID` нельзя: демон вцепится в чужой порт, а соседний
демон останется без своего. Так уже ломалось — `Find-BoardPort` брала
`Select-Object -First 1` из двух одинаковых кандидатов, и после переподключения
плат через USB-хаб порядок перечисления сменился: `os-switcher-rebootd` сел на
порт `off-screen` (в логе `игнорирую неизвестную строку: OFF`), а `off-screend`
не смог открыть свой порт (`Доступ к порту 'COM9' закрыт`) и долбился в него
раз в 4 секунды. **Оба проекта умерли разом, физически при этом всё исправно.**
В Windows имя достаётся из `DEVPKEY_Device_BusReportedDeviceDesc`
(`Get-BusReportedName`) — это аналог пути `by-id` в Linux, и ломается он ровно
от того же. Ветка «единственный кандидат зовётся чужим именем → это не наша
плата, жду свою» существенна: без неё демон снова заберёт чужой порт, когда
своей платы нет в системе.

**Имя платы ставится сборкой, и снимать флаги из `Makefile` нельзя.** Цель
`build` обязана звать `arduino-cli` с обоими флагами — `--clean` **и**
`--build-property build.usb_product`. Без второго плата назовётся `Arduino
Leonardo`, как соседняя, и опознавание из предыдущего пункта развалится: два
кандидата, имя ни у одного не подтверждается, демон пишет «плата не найдена» и
стоит. Без `--clean` кешируется ядро (вместе с `USBCore.cpp`, где живёт имя), и
сборка молча даст прошивку со старым именем — правки имени при этом просто не
видно. Флагов здесь долго не было вовсе: плата отвечала `os-switcher` только
потому, что её однажды прошили с флагом руками, и первый же обычный `make
flash` тихо сломал бы поиск платы.

**Перед прошивкой освободить порт.** Демон держит его открытым, а upload дёргает
порт на 1200 бод и ждёт загрузчика. В Linux этим занимается `make flash` — он
останавливает сервис и поднимает обратно, поэтому там шить только им. В Windows
`make` не работает вовсе, и сервис надо снимать руками:
`Stop-ScheduledTask -TaskName os-switcher-rebootd` плюс `Stop-Process` для
осиротевшего процесса (см. отдельный инвариант ниже), а после прошивки —
`Start-ScheduledTask`.

**Прошить можно и из Windows**, если Linux-стороны под рукой нет. `arduino-cli`
лежит внутри Arduino IDE (`resources\app\lib\backend\resources\arduino-cli.exe`),
ядро `arduino:avr` обычно уже стоит. Флаги — те же, что в `Makefile`, иначе
плата потеряет имя:

```powershell
& $cli compile --clean --fqbn arduino:avr:leonardo `
    --build-property 'build.usb_product="os-switcher"' `
    --upload -p COM3 os-switcher-sketch
```

Что имя действительно попало в сборку, видно по `-DUSB_PRODUCT="os-switcher"`
в команде компилятора при `--verbose`.

**Библиотеку `HID-Project` с этой машины `arduino-cli lib install` не ставит** —
`downloads.arduino.cc` недоступен (сброс соединения, а на файлах ещё и
просроченный TLS-сертификат), при этом GitHub открывается нормально. Ставится
руками: репозиторий называется `NicoHood/HID`, **не** `HID-Project`, релиз
`2.8.4` (`HID-<версия>.tar.xz`, рядом лежит `.sha512` — сверить), распаковать в
`%USERPROFILE%\Documents\Arduino\libraries\HID-Project`. Имя каталога должно
быть именно таким: скетч инклюдит `HID-Project.h`.

**Сразу после прошивки плата печатает клавиши.** Для скетча переподключение
неотличимо от загрузки ПК: `armed` взводится, и через `INPUT_DELAY_MS` (15 с)
уходит `Enter` либо 4 × «вниз» + `Enter` — в активное окно рабочего стола, а не
в GRUB. Шьёшь на живой системе — не держи в фокусе окно, где эти нажатия
что-нибудь натворят.

**`Write-Log` пишет через `Write-Host`, и менять это нельзя.** С `Write-Output`
строка лога уходит в конвейер и становится частью возвращаемого значения той
функции, откуда позвали лог. `Find-BoardPort` и пишет в лог, и возвращает имя
порта — с `Write-Output` она вернёт `[строка лога, "COM3"]`, и открытие порта
упадёт на приведении типа. В `off-screen` этот капкан уже срабатывал на
`New-SinkWindow`: кнопка молча умерла, а в логе была только жалоба на
`System.Object[]`.

**Повторяющиеся состояния логируются через `Write-LogOnce`.** «Плата не
найдена» и «порт занят» приходят каждые `$RetrySec`; писать их каждый раз —
это мегабайты за ночь с выдернутой платой, и ротация съедает всё, что было до.
`Write-Log` при этом намеренно сбрасывает глушитель, так что обычное событие
всегда пишется, а следующее ожидание описывается заново.

**Демон запускается от пользователя, а не службой.** Toast-уведомления живут в
сессии пользователя, из сессии 0 их не показать. Перезагрузить машину
интерактивный пользователь может и без прав администратора. Обратная сторона:
пока никто не залогинен, щелчок выключателя ничего не сделает.

**`Unregister-ScheduledTask` не убивает уже запущенный демон.** Задача стартует
через `run-hidden.vbs`, и снятие задачи убивает `wscript`-лаунчер, а
дочерний `powershell.exe` остаётся сиротой и продолжает держать COM-порт —
переустановленный демон при этом выглядит рабочим, но порт занят призраком.
Ловилось живьём. После переустановки проверяй, что процесс со скриптом в
командной строке остался ровно один.

**`.ps1` сохранять в UTF-8 с BOM.** Windows PowerShell 5.1 без BOM читает файл
как ANSI, и русский текст в логе становится кракозябрами.

**Триггер перевзводится по сбросу шины, а не по suspend**, и сбросы в течение
`REARM_LOCKOUT_MS` после срабатывания игнорируются — иначе загрузка выбранной
ОС перевзводит триггер и запускает вторую итерацию уже в рабочем столе.
Подробности и псевдокод — в README.

## Как проверить, что работает

Выключателя может не быть — замкни `D2` на `GND` пинцетом и смотри журнал:
должны пойти `COUNTDOWN` и уведомление с отсчётом. Отпустишь до конца отсчёта —
`CANCEL`. **Досчитает до конца — машина уйдёт в реальную перезагрузку**, так
что проверяй на сохранённой работе.

Linux: `make service-logs`.
Windows: `Get-Content "$env:LOCALAPPDATA\os-switcher\rebootd.log" -Tail 20 -Wait`.

Ожидаемая строка — `слушаю COMx`; сверь номер порта с тем, что показывает
диспетчер устройств для платы с именем `os-switcher`, а не для соседней.

Руками, чтобы видеть вывод живьём: `Stop-ScheduledTask -TaskName
os-switcher-rebootd` (освободить порт), затем `.\os-switcher-rebootd.ps1`.
Порт можно навязать: `.\os-switcher-rebootd.ps1 -PortName COM3`.

**Плата молчит, хотя порт открылся** — самый частый симптом, и путать его с
проблемой порта не надо. Проверять прямым чтением, не через демон: остановить
демон, открыть порт (9600, `DtrEnable = $true` — без DTR ядро Arduino
выбрасывает всё, что пишет скетч) и щёлкнуть выключателем. Пришёл `COUNTDOWN` —
плата в порядке, разбирайся с хостом. Тишина — либо выключатель не доходит до
`D2`, либо **в плате прошивка старее reboot-функции**: она умеет только жать
клавиши в GRUB и про serial-протокол не знает вовсе. Второе уже ловилось и
выглядит один в один как исправная плата: USB жив, HID работает, порт
открывается, светодиод моргает на трафик — а по serial тишина. Лечится
перепрошивкой. Проверять при этом надо именно перезагрузку по щелчку: «выбор ОС
в GRUB работает» о reboot-функции не говорит ничего, это разные половины
проекта.

Что на живой Windows-машине проверено: демон стартует задачей планировщика,
находит свою плату среди двух с одинаковым `VID:PID` и садится на её порт;
прошивка из Windows проходит и имя платы переживает её; щелчок выключателя даёт
`COUNTDOWN 10`, возврат — `CANCEL` (снято прямым чтением порта, многократно).
**Не проверены** toast-уведомления, отсчёт на экране и перезагрузка по `REBOOT`,
а также ветки `-PortName` и `-Uninstall` — за проверенные их не выдавай.

## Соседний проект

`off-screen` — та же схема (Pro Micro + демон на хосте) и общий с этим проектом
`VID:PID`. Оттуда взяты `Find-BoardPort`/`Get-BusReportedName`/`Write-LogOnce`;
если правишь поиск платы или логирование здесь, посмотри, не надо ли то же
самое там — расхождение между ними уже приводило к описанному выше отказу
обоих. Его udev-правило и правило этого проекта закрывают ModemManager для
одного и того же `VID:PID`.
