# Установка os-switcher

Пошагово: от голой платы до «щёлкнул выключателем — машина перезагрузилась в
другую ОС». Про то, *почему* всё устроено именно так, — в [README.md](README.md).

Порядок такой: сначала железо и прошивка (шаги 1–4) — этого уже хватает, чтобы
плата выбирала пункт в GRUB. Сервисы (шаги 5–6) нужны только для перезагрузки
по щелчку в уже загруженной системе, и ставятся отдельно в каждой ОС.

## Что нужно

- Плата на **ATmega32u4**: Arduino Pro Micro, Leonardo или совместимая.
  Nano/Uno **не подойдут** — у них нет аппаратного USB и они не умеют
  прикидываться клавиатурой.
- Любой двухпозиционный выключатель (тумблер, клавишный от люстры) и два
  провода.
- `arduino-cli` или Arduino IDE с установленным ядром `arduino:avr`.
- Библиотека **HID-Project**.
- Настроенный GRUB, из которого грузятся обе ОС.

## 1. Подключить выключатель

- Один провод — на пин **GND**.
- Второй — на пин **2** (цифровой D2; на шелкографии подписан просто «2»,
  пятый по левому краю от USB-разъёма: TX0, RX1, GND, GND, **2**).
  Не путать с «A2» — это другой, аналоговый пин.

Полярность не важна, внешний резистор не нужен: пин работает в режиме
`INPUT_PULLUP`.

Плату воткнуть в **USB на материнской плате** (не в хаб и не в порт, который
обесточивается при выключении ПК, — иначе не поймается момент включения).

## 2. Поставить библиотеку HID-Project

```bash
arduino-cli lib install "HID-Project"
```

или вручную — распаковать в `~/Arduino/libraries/HID-Project`.
В Arduino IDE: Sketch → Include Library → Manage Libraries → «HID-Project».

## 3. Подогнать скетч под свой GRUB

Два значения в `os-switcher-sketch/os-switcher-sketch.ino` зависят от машины —
их надо проверить **до** прошивки:

| Что | Где | Как подобрать |
|-----|-----|---------------|
| Сколько раз жать «вниз» | `sendKeys(switchIsOn() ? 0 : 4)` в `loop()` | посчитать в меню GRUB, сколько нажатий «вниз» от верхнего пункта до нужного (по умолчанию 4) |
| Пауза до нажатий | `INPUT_DELAY_MS` (15 с) | должна попасть в промежуток «меню GRUB уже показано, но таймаут ещё не вышел» |

Про паузу: отсчёт идёт с момента, когда хост проэнумерировал плату (ранний
POST), а меню GRUB появляется позже. Коротко — нажатия уйдут в пустоту, длинно —
GRUB успеет загрузить пункт по умолчанию. Проще всего засечь секундомером от
включения питания до появления меню и прибавить пару секунд.

## 4. Прошить

```bash
make ports    # найти порт платы
make flash    # собрать и прошить
```

`make` берёт `arduino-cli` по пути из переменной `CLI` — если он лежит
в другом месте, задать явно: `make flash CLI=/usr/bin/arduino-cli`.
Порт тоже можно указать руками: `make flash PORT=/dev/ttyACM0`.

Без `make`:

```bash
arduino-cli compile --fqbn arduino:avr:leonardo os-switcher-sketch
arduino-cli upload -p /dev/ttyACM0 --fqbn arduino:avr:leonardo os-switcher-sketch
```

FQBN — именно `leonardo`: Pro Micro определяется в системе как Leonardo, чип
один и тот же.

**Проверка.** Перезагрузить ПК и смотреть на задний RX-светодиод: он должен
начать медленно мигать (0.5 с) вскоре после включения и погаснуть через 15
секунд, а меню GRUB — само выбрать пункт. Положение выключателя можно менять,
пока светодиод мигает: оно читается в самом конце, прямо перед нажатиями.

На этом базовая функция готова. Дальше — только перезагрузка по щелчку.

## 5. Сервис в Linux

```bash
sudo apt install python3-serial   # если ещё нет
make install-service              # спросит sudo
make service-logs                 # проверить, что порт нашёлся
```

В логе должна быть строка `слушаю /dev/serial/by-id/usb-Arduino_LLC_...`.

Что именно ставится:

| Файл | Куда | Зачем |
|------|------|-------|
| `host/linux/os-switcher-rebootd.py` | `/usr/local/bin/os-switcher-rebootd` | сам сервис |
| `host/linux/os-switcher-rebootd.service` | `/etc/systemd/system/` | автозапуск через systemd |
| `host/linux/99-os-switcher.rules` | `/etc/udev/rules.d/` | запрет ModemManager лезть в порт платы своими AT-командами (по умолчанию он считает любой `ttyACM` кандидатом в модемы) |

**Проверка без перезагрузки.** Сервис работает от root и по-настоящему
перезагружает машину, поэтому первый прогон лучше сделать вручную с подменённой
командой:

```bash
sudo systemctl stop os-switcher-rebootd   # иначе порт занят
OS_SWITCHER_REBOOT_CMD="echo ПЕРЕЗАГРУЗКА-БЫЛА-БЫ-ЗДЕСЬ" \
    python3 host/linux/os-switcher-rebootd.py
# щёлкнуть выключателем: должно появиться уведомление с обратным отсчётом,
# а через 10 секунд в консоли — строка вместо перезагрузки
sudo systemctl start os-switcher-rebootd
```

Переменные окружения сервиса: `OS_SWITCHER_PORT_GLOB` (шаблон пути к порту),
`OS_SWITCHER_BAUD` (по умолчанию 9600), `OS_SWITCHER_REBOOT_CMD` (по умолчанию
`systemctl reboot`).

Снять всё — `make uninstall-service`.

## 6. Сервис в Windows

> На живой Windows 11 проверены установка без прав администратора, автозапуск,
> поиск своей платы среди двух с одинаковым `VID:PID` и протокол платы
> (`COUNTDOWN` по щелчку, `CANCEL` по возврату). Уведомления и сама
> перезагрузка вживую не гонялись — первый щелчок выключателя стоит сделать
> на сохранённой работе.
>
> Если демон нашёл порт, а щелчок ничего не даёт — скорее всего в плате
> прошивка старее reboot-функции: выбор ОС в GRUB она умеет, а слать
> `COUNTDOWN` — нет. Диагностика и обход — в `CLAUDE.md`.

Из-под Windows (в PowerShell, **без** прав администратора):

```powershell
cd host\windows
powershell -ExecutionPolicy Bypass -File install.ps1
```

Установщик кладёт демон в `%LOCALAPPDATA%\os-switcher\`, регистрирует задачу
планировщика `os-switcher-rebootd` с запуском **при входе в систему** и сразу
её стартует.

Проверить:

```powershell
Get-Content "$env:LOCALAPPDATA\os-switcher\rebootd.log" -Tail 20 -Wait
```

Ожидаемая строка — `слушаю COMx`. Если вместо неё `плата не найдена`, посмотри
в диспетчере устройств, виден ли COM-порт (Arduino Leonardo); может не хватать
драйвера.

Прогнать демон в консоли, чтобы видеть его вывод живьём:

```powershell
Stop-ScheduledTask -TaskName os-switcher-rebootd   # освободить порт
.\os-switcher-rebootd.ps1
```

Снять — `powershell -ExecutionPolicy Bypass -File install.ps1 -Uninstall`.

**Почему от пользователя, а не службой от SYSTEM.** Toast-уведомления живут в
сессии пользователя, и служба из сессии 0 показать их не может. Перезагрузка же
от обычного пользователя работает: право «Завершение работы системы» у
интерактивных пользователей клиентской Windows есть по умолчанию. Обратная
сторона — пока никто не залогинен, щелчок выключателя ничего не сделает.

## 7. Проверка целиком

1. Загрузиться в любую из ОС, дождаться рабочего стола.
2. Щёлкнуть выключателем. Должно появиться уведомление с обратным отсчётом, а
   RX-светодиод — **часто** замигать (0.1 с).
3. Вернуть выключатель назад: отсчёт отменяется, светодиод гаснет, уведомление
   меняется на «Отменено».
4. Щёлкнуть и не возвращать. Через 10 секунд — штатная перезагрузка, а в меню
   GRUB плата сама выберет пункт, соответствующий новому положению.

## Обновление прошивки

```bash
make flash
```

`make flash` сам останавливает Linux-сервис на время заливки и поднимает
обратно: сервис держит порт открытым, а `arduino-cli upload` дёргает порт на
1200 бод и ждёт появления загрузчика. Если шьёшь вручную — останови сервис сам
(`sudo systemctl stop os-switcher-rebootd`), в Windows — `Stop-ScheduledTask
-TaskName os-switcher-rebootd`.

## Если что-то не работает

| Симптом | Причина и что делать |
|---------|----------------------|
| Светодиод вообще не мигает при включении ПК | плата не в том USB-порту (обесточивается) либо прошивка не залилась — проверь `make flash` |
| Мигает, но GRUB не реагирует | нажатия попали мимо окна меню — подбери `INPUT_DELAY_MS` |
| Выбирается не тот пункт меню | не то число нажатий «вниз» — поправь `sendKeys(...)` |
| Вторая итерация нажатий уже в загруженной ОС | ядро сбросило USB-шину позже локаута — увеличь `REARM_LOCKOUT_MS` |
| Отсчёт идёт (светодиод часто мигает), но машина не перезагружается | сервис не запущен или не открыл порт: `make service-logs` (Linux), `rebootd.log` (Windows) |
| Уведомления нет, но перезагрузка происходит | Linux: нет `notify-send` или не нашлась активная графическая сессия (сервис пишет об этом в лог). Windows: не поднялся toast-API, смотри лог |
| В логе Linux-сервиса порт то и дело отваливается | ModemManager лезет в порт — проверь, что правило udev установлено: `udevadm info /dev/ttyACM0 \| grep ID_MM_DEVICE_IGNORE` |

## Удаление

```bash
make uninstall-service                                        # Linux
powershell -ExecutionPolicy Bypass -File install.ps1 -Uninstall  # Windows
```

Прошивка при этом остаётся: плата продолжит выбирать пункт в GRUB, перестанет
работать только перезагрузка по щелчку. Чтобы убрать и её — залить в плату
любой другой скетч.
